# ImHamster 统一术语表

> 更新：2026-10-11。本文是产品设计、开发计划、提示词、界面和运行记录的统一术语来源。目标概念与现有代码字段分开说明。

## 1. 任务与执行

| 术语 | 全称 | 定义 |
|---|---|---|
| Task | Task，任务 | 用户下发的语义指令，分为 OST 和 EDT。复杂指令可由 LLM 拆解成内部工作单元，不增加新的产品任务类型。 |
| OST | One-shot Task，单次任务 | 一次具体执行，来自立即执行的用户指令，或一次 EDT 触发。是软件层面时间、额度、状态和结果记录的管理单位。 |
| EDT | Event-driven Task，事件驱动任务 | 保存触发条件和执行意图的任务，可以触发一次或多次，每次触发生成独立 OST。EDT 等待与监听本身没有 OST 的时间上限。 |
| AL | Action Loop，动作循环 | LLM 连续进行观察、理解、动作、复核的执行阶段。OST 通常对应一个 AL，也可在恢复或换路后由新的 AL 继续。AL 不等同于 OST，也不等同于一次模型请求或一个动作。 |
| 内部工作单元 | Internal Work Unit | LLM 为复杂任务组织的子目标、进展和依赖，属于任务计划；不是额外的 Task 类型，也不必对应单独 AL。 |
| HO | Hamster Orchestrator，编排器 | 协调 EDT、OST、AL 的生命周期、事件交付、调度、资源、时间/额度和持久化；不决定具体操作内容，也不独立评估任务是否做好。 |

## 2. 上下文、自我模型与积累

| 术语 | 全称 | 定义 |
|---|---|---|
| CAE | Context Assembly Engine，上下文组装引擎 | 按当前任务与调用目的检索、选择、压缩和组装上下文，衔接 SM、ME、TE、任务进展和观察结果，记录所用来源。替代旧名称 PE。 |
| SM | Self-model，自我模型 | ImHamster 对自身的持久模型，包含 Persona 和 Memory。它是数据模型与读取视图，不是独立调度器或新增后台服务。 |
| Persona | Persona，角色设定 | 由稳定的 IC 和动态可变的 BP 组成；表达身份、人格和行为倾向。 |
| IC | Identity Core，身份核心 | 稳定的人格核心文档。由用户明确编辑和版本化，日常执行与自主学习不自动改写。 |
| BP | Behavior Patterns，行为模式 | 动态数据库中的情境化行为倾向，例如沟通风格、做事习惯。可以基于经验调整，有作用范围、来源和版本，不升级为不可撤销的身份核心。 |
| Memory | Memory，记忆 | 记忆与经验的统一称呼；数据库保存事实、事件、关系背景、自我叙事、可复用经验及其来源。由 ME 管理。原始截图、日志和资料不自动等同于 Memory。 |
| ME | Memory Engine，记忆引擎 | 管理 Memory 的收集、整理、存储、检索、更新与遗忘，为 CAE 提供相关记忆和经验。LLM 判断应记住什么，ME 落实数据操作。 |
| TE | Tool Engine，工具引擎 | 管理内置工具与积累的工具配方，检索并提供给 CAE，执行 LLM 选择的工具。LLM 判断工具用途与是否值得积累；TE 校验格式、参数和可用能力。 |
| 工具配方 | Tool Recipe | 有参数、步骤与适用条件的可复用工具组合，只调用已注册能力。它属于 TE，不属于 Persona 或 Memory；Memory 可引用它。 |

## 3. 关系与责任边界

```text
Task
├── OST → AL → 必要时新的 AL 继续同一 OST
└── EDT → 每次触发创建独立 OST

HO：维护上述生命周期并调度执行
CAE：为 LLM 的当前调用组装上下文
SM
├── Persona
│   ├── IC：稳定文档
│   └── BP：动态数据库
└── Memory：记忆与经验数据库，由 ME 管理
TE：工具与工具配方库，供 CAE 检索、供 LLM 调用
```

- OST 默认软件硬时限为 **30 分钟**，涵盖全部 AL。排队不计时；开始执行后保存截止时间，暂停、恢复、换路和重启 AL 不重置它。当前模型额度不设上限。
- AL 默认预估预算为 **15 分钟**。执行前由 LLM 估算，单次设置不超过 30 分钟且不超过 OST 剩余时间。预算到期触发复盘，不等于失败；LLM 决定延长、换 AL 从现状继续，或用新 AL 从头尝试。
- OST 硬时限到期由 HO 停止并报告软件层面的超时失败。用户重试创建新 OST，并关联原记录；不能通过自动新建 OST 绕过时限。
- LLM 决定任务拆解、语义触发匹配、操作、恢复、策略与验收。HO 保存 LLM 的完成结论；校验消息格式、授权、时间和资源不等于语义验收。
- HO 调度必要的学习维护；ME、TE 提供检索和存储。BP 属于 Persona，其存取由 SM 的数据访问层负责；ME 可提供学习依据，不因此取得改写 IC 的职责。
- 机械操作可只使用目标、进展、工具与相关经验。需要身份、沟通风格或关系背景时，再取用 IC、BP 与相关 Memory。

## 4. 旧代码映射与迁移约束

当前生产 Worker 仍使用历史命名，尚未完整实现上述模块：

| 现有名称 | 当前含义 | 升级处理 |
|---|---|---|
| `Goal` / `goalId` / `active-goal` | 用户意图与当前 OST 状态的混合记录 | 一次性迁移到按 `kind: ost/edt` 区分的任务记录；不保留第二套运行主路径。 |
| 旧 `Task` / `taskId` | 旧设计中的内部工作单元 | 转入 OST 的计划/进展，不直接当作用户 Task。 |
| `runId` | 当前执行尝试的关联标识 | 迁移时对应 OST；恢复沿用，明确重试建立新 OST。 |
| `actionLoop` / 旧 `loop` | 当前 AL 状态 | 新模型保存独立 AL 历史；旧 `loop` 只在一次性迁移中读取。 |
| `knowledge` 的 `experience` | 零散经验条目 | 根据内容迁入 Memory；保留来源。 |
| `tool-candidate` | 名称、描述与工具引用的候选条目 | 属于 TE 候选资料；不宣称已经是可执行工具配方。 |
| PE / Prompt Engine、旧“上下文引擎” | 历史设计名称 | 新增文档和代码统一为 CAE；旧文档作为历史记录保留。 |

描述 LLM 连续执行阶段时使用 AL，不再使用“任务 loop”或“任务循环”。迁移细节与实施顺序见[开发升级计划](../plans/DEVELOPMENT_UPGRADE_PLAN_2026-10-11.md)。
