# ImHamster 产品与编排术语表

本文是 ImHamster 产品文档、提示词、运行记录和界面文案的统一术语来源。产品语义与现有存储字段分开说明，避免为统一名词而破坏已有数据。

| 术语 | 全称 | 定义 |
|---|---|---|
| Task | Task（用户任务） | 用户下发的一条语义指令。它定义用户希望 ImHamster 做什么，可立即执行，也可持续等待事件。复杂 Task 可以由 LLM 拆解成内部工作单元。 |
| OST | One-shot Task（单次任务） | Task 的一次具体单次执行。用户要求立即执行时创建 OST；EDT 每次触发时也创建一个新的 OST。OST 是软件层面计时与运行管理的单位。 |
| EDT | Event-driven Task（事件驱动任务） | 长期有效的 Task 定义，等待一个或多个事件并决定是否触发执行。EDT 可以触发零次、一次或多次；EDT 的持续监听时间不受 OST 时限约束。每次触发各自创建 OST。 |
| AL | Action Loop（动作循环） | LLM 在一个执行阶段内反复进行观察、理解、动作和结果评估的过程。AL 到预算检查点时，LLM 复盘并决定延长当前 AL、结束后创建新 AL 继续当前 OST，或用新 AL 重新开始。 |
| 内部工作单元 | Internal Work Unit | LLM 为完成复杂 Task/OST 自行拆分、依赖和调度的子目标。它服务于任务推进，不改变用户语义 Task 的身份，也不与 AL 等同。 |

## 关系与时间边界

```text
用户语义指令 Task
├── 立即执行 → 一个 OST
└── 持续事件触发 → EDT → 每次触发创建一个独立 OST

OST → 通常一个 AL；需要恢复或换路时，同一个 OST 可继续经历多个 AL
```

- 一个 OST 通常对应一个 AL，但 OST 不等同于 AL。AL 结束不代表 OST 完成或失败。
- 一个 OST 的软件层面默认最长时间为 30 分钟，涵盖其全部 AL。新建 AL、重启 AL 或切换策略都不能重置这段时间。超过 OST 上限后，编排器按软件规则停止并报告。
- 一个 AL 默认预算为 15 分钟。LLM 在该 AL 开始动作前估算预算，预算需覆盖预估且不得超过 30 分钟。AL 到预算是检查点而非失败；LLM 负责复盘并选择如何继续。
- EDT 不受单个 OST 的 30 分钟上限约束。每个触发产生独立 OST，并单独计时；一次 OST 完成或超时不自动停止 EDT。
- 编排器管理 AL 生命周期及 OST 时间/额度配置、调度和记录；LLM 决定具体内容、拆解、操作策略、恢复路径和任务结果验收。编排器只保存 LLM 的验收结论，不再做语义验收。
- 当前模型额度不设上限。

## 代码兼容映射

当前实现保留历史存储名称，产品术语不要求立即重命名数据库字段：

| 现有代码/数据名 | 当前承载含义 | 约束 |
|---|---|---|
| `Goal` / `goalId` / `active-goal` | 用户 Task/EDT 配置和当前 OST 运行状态的历史记录 | 兼容字段；新用户文案称 Task、OST 或 EDT，按实际语义选择。 |
| `Task` / `taskId` | 旧架构中的内部工作单元 | 不要把它误称为用户下发的 Task；必要时使用“内部工作单元”。 |
| `runId` | 一次 OST 执行尝试的标识 | 恢复同一次 OST 时沿用；用户明确重试并创建新尝试时再更新。 |
| `actionLoop` | 当前 AL 的持久状态 | 旧记录中的 `loop` 仅作为迁移兼容字段读取；新记录与新界面统一使用 AL/`actionLoop`。 |

“循环”一词仅用于一般程序控制结构时可按上下文使用。描述 LLM 的连续屏幕操作阶段时必须称为 AL，不称为任务循环或 task loop。
